    Working with AI AI와 일하는 방식

    판단과 검증은 사람, 구현과 측정은 AI. People decide and verify. AI builds and measures.

    VRChat 기믹 4종을 AI 코딩 에이전트(Claude Code)와 함께 개발. 본인의 몫은 코드를 직접 타이핑한 양이 아니라 무엇을 만들지 정하고 결과를 어떻게 검증했는지. I decide what to build and how to verify it; the agent writes the code.

    작업 흐름 Workflow

    1. 명세와 결정 기록 Spec & decision log

      프로젝트마다 현재 상태, roadmap, 명세 문서 유지. 결정은 D번호, 위험은 R번호로 기록

      한 프로젝트의 명세·작업 기록 문서가 1,000~2,000줄 규모

    2. 위임 Delegate

      에이전트가 MCP로 Unity 에디터를 직접 조작

      프로젝트마다 포트를 나눠 여러 세션이 섞이지 않게 구성. 개발 프로젝트와 "받는 사람 쪽" 시험 프로젝트 분리

    3. 다중 에이전트 검토 Multi-agent review

      읽기 전용 에이전트 여러 개가 영역별로 검토, 결과를 교차 대조

      한 번의 전체 검토에 에이전트 6개. 두 에이전트가 따로 찾은 항목과 직접 확인한 항목을 구분 표시

    4. 근거 수준 표시와 기준선 대조 Evidence levels & baselines

      발견마다 심각도(S1~S5)와 근거 수준(재현됨 / 코드 추론 / 가설) 표기

      수정 전후 빌드 결과를 golden 해시로 대조해 바이트 단위로 같은지 확인. 확인하지 못한 것은 "미확인"으로 그대로 기록

    5. 인게임 실기 판정 In-game verdict

      여러 시험 아바타에 붙여 비공개로 올린 뒤 VR·인게임에서 본인이 직접 판정

      에디터에서 통과해도 인게임에서 불합격이면 불합격

    사례 Case studies

    Drink Can

    깨진 배포 파일 The broken package

    무슨 일 What happened
    • 문서 표기 한 줄을 고치려고 Unity 없이 스크립트로 패키지를 다시 묶음
    • 검증은 바이트 비교와 해시뿐, 실제 임포트는 해 보지 않음
    어떻게 잡혔나 How it was caught
    • 받는 사람의 제보("더블클릭해도 아무 일도 안 일어남")로 발견. 깨진 파일이 572회 다운로드된 뒤
    • 압축 형식 2종 × 헤더 이름 2종을 대조해 원인 분리(0 / 0 / 126 / 126개 임포트)
    • 원인: 압축 헤더의 파일 이름에 따라 Unity가 오류 없이 건너뜀
    무엇이 바뀌었나 What changed
    • 제보 당일 수정판 배포와 공지
    • 새 규칙: 올릴 파일은 직접 풀어 빈 프로젝트에 임포트하고 파일 수까지 확인한 뒤에만 업로드
    • 이 절차를 뒤의 모든 프로젝트에 적용

    Sleeve Roll

    "재현 안 됨" 보고가 틀림 A wrong "cannot reproduce"

    무슨 일 What happened
    • 에이전트가 인게임 실패를 "재현 안 됨"으로 보고
    • 본인이 인게임 스크린샷으로 반박. 에이전트가 이미 찍어 둔 비교 렌더의 틈을 "작은 틈"으로 넘겼던 것으로 확인
    어떻게 잡혔나 How it was caught
    • 이후 수정도 인게임에서 연속 실패
    • 원인: 확인 렌더의 거리가 멀어 결함이 보이지 않았음
    • 근접 렌더와 깊이 측정을 넣자 재현됨
    무엇이 바뀌었나 What changed
    • 본인이 방향 전환: 옷마다 대응하지 않고 일반 알고리즘으로
    • 만든 쪽과 다른 평가 에이전트가 판정. 평가 전용 데이터는 만드는 쪽에 넘기지 않음. 합격 기준은 낮추지 않음
    • 6세대에서 멈추도록 본인이 결정. 자체 기준 불합격이 남은 상태였고, 인게임 판정에서 양호로 확인
    • 남은 불합격과 위험은 문서에 그대로 남김

    Drink Can

    수치는 개선, 체감은 기각 Better numbers, rejected in play

    무슨 일 What happened
    • 캔 교체 순간의 2프레임 공백
    • 에이전트가 없애는 방식을 28개 조합으로 측정해 공백 0/28 달성
    어떻게 잡혔나 How it was caught
    • 본인 인게임 판정: 깜빡임보다 두 캔이 겹쳐 보이는 쪽이 더 어색함
    무엇이 바뀌었나 What changed
    • 되돌림
    • 남은 원칙: 수치 개선 ≠ 체감 개선. 최종 판정은 실기

    가드레일 Guardrails

    • 파일은 영구 삭제하지 않고 별도 폴더로 이동
    • 공개·업로드·배포 같은 외부 작업은 본인 동의 후
    • 유료 아바타에서 나온 데이터(메시, 셰이프키 값, 텍스처)는 배포물에 넣지 않음
