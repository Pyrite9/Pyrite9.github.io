    Working with AI AI와 일하는 방식

    판단과 검증은 사람, 구현과 측정은 AI. People decide and verify. AI builds and measures.

    VRChat 기믹 4종을 AI 코딩 에이전트(Claude Code)와 함께 개발. 본인의 몫은 코드를 직접 타이핑한 양이 아니라 무엇을 만들지 정하고 결과를 어떻게 검증했는지. I decide what to build and how to verify it; the agent writes the code.

    작업 흐름 Workflow

    1. 명세와 결정 기록 Spec & decision log

      프로젝트마다 현재 상태, roadmap, 명세 문서 유지. 결정은 D번호, 위험은 R번호로 기록

      한 프로젝트의 명세·작업 기록 문서가 1,000~2,000줄 규모

    2. 위임 Delegate

      에이전트가 MCP로 Unity 에디터를 직접 조작

      프로젝트마다 포트를 나눠 여러 세션이 섞이지 않게 구성. 개발 프로젝트와 "받는 사람 쪽" 시험 프로젝트 분리

    3. 다중 에이전트 검토 Multi-agent review

      읽기 전용 에이전트 여러 개가 영역별로 검토, 결과를 교차 대조

      한 번의 전체 검토에 에이전트 6개. 두 에이전트가 따로 찾은 항목과 직접 확인한 항목을 구분 표시

    4. 근거 수준 표시와 기준선 대조 Evidence levels & baselines

      발견마다 심각도(S1~S5)와 근거 수준(재현됨 / 코드 추론 / 가설) 표기

      수정 전후 빌드 결과를 golden 해시로 대조해 바이트 단위로 같은지 확인. 확인하지 못한 것은 "미확인"으로 그대로 기록

    5. 인게임 실기 판정 In-game verdict

      여러 시험 아바타에 붙여 비공개로 올린 뒤 VR·인게임에서 본인이 직접 판정

      에디터에서 통과해도 인게임에서 불합격이면 불합격

    세대 반복 탐색 Generational search

    에이전트가 후보 알고리즘을 만들고, 다른 에이전트가 평가하고, 불합격 사유로 다음 세대를 만듦. 멈출 시점과 최종 판정은 사람. Agents build and grade candidates generation by generation; a person decides when to stop and gives the final verdict.

    실제 기록 Real run · Sleeve Roll

    처진 소매 정규화 알고리즘 Normalizing drooping sleeves

    계기 처진 소매 의상에서 인게임 판정이 세 번 연속 실패. 본인이 방향 전환 지시: 옷마다 대응하지 말고 일반 알고리즘을 세우고, 합격할 때까지 세대 반복

    1. 1세대 자체 기준 불합격

      막힌 곳 일반 옷에서 오작동

    2. 2세대 자체 기준 불합격

      막힌 곳 후보마다 일반 옷 결과가 바뀜, 잡음, 뒤집힘

    3. 3세대 자체 기준 불합격

      막힌 곳 기본값은 대부분 통과. 특정 슬라이더 조합에서 처진 소매 실패

    4. 4세대 자체 기준 불합격

      막힌 곳 기본값 처진 소매 12개와 렌더 통과. 슬라이더 95개 설정 중 19개가 기존 방식보다 나쁨

      인게임 첫 양호 판정 (본인)

    5. 5세대 자체 기준 불합격

      막힌 곳 기준 5개 항목에서 불합격

    6. 6세대 자체 기준 불합격

      막힌 곳 기준 2개 항목만 남고 나머지 9개 통과

      본인이 여기서 중단 결정

    결말 6세대를 시험 아바타 6개에 올려 본인이 인게임에서 전부 확인, 양호 판정 후 배포. 자체 기준의 불합격 2개 항목과 남은 위험 6가지는 심각도 순으로 문서에 그대로 기록

    이 방식이 성립하는 규칙 Rules that make it work

    1. 만드는 에이전트와 평가하는 에이전트를 분리Builder and evaluator are different agents
    2. 평가 전용 데이터의 세부는 만드는 쪽에 넘기지 않음ML의 train / test 분리와 같은 발상Held-out evaluation data
    3. 합격 기준은 낮추지 않음기준을 네 번 고쳤고(v1 → v4) 전부 항목 추가나 재정의, 이유를 기록The bar is never lowered
    4. 수치상 불합격이 남아도 숨기지 않음최종 판정은 사람의 인게임 실기Remaining failures stay on record

    같은 방식의 다른 예 · Drink Can 쥐는 손 자동 맞춤

    • 관점이 다른 AI 평가자 4명(접촉 / 관절 / 실제 쥐는 법 / 알고리즘)이 렌더를 보고 7라운드 반복, 평균 5점 → 7.3점
    • 마지막에는 이름을 가린 블라인드 비교로 고정 자세와 대결시켜 자동 맞춤을 기본값으로 채택
